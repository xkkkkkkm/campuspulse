# 校园活动智能推荐与组队平台期末展示操作说明书

## 1. 文档用途

本说明书面向期末展示现场的老师体验环节，目标是帮助老师在最短时间内完成一次完整、顺畅的软件体验。

如果项目已经由演示者提前启动，老师只需要打开浏览器访问前端地址即可，不需要手动部署数据库或运行代码。

## 2. 推荐访问方式

请优先使用以下地址访问系统：

- 前端体验入口：`http://127.0.0.1:8125/`
- 后端服务地址：`http://127.0.0.1:8080/`

注意：

- 不要直接双击 HTML 文件或使用 `file://` 打开页面，否则可能出现 `Failed to fetch`。
- 建议所有体验都从 `8125` 入口进入，因为该入口已经将前端静态页面和后端接口联调到同一地址下，最稳定。

## 4. 体验前准备

如果系统已经由项目负责人提前启动，可直接跳到第 5 节。

如果需要现场自行启动，请确保：

1. MySQL 已启动。
2. 后端服务已启动在 `8080` 端口。
3. 本地 HTTP 代理已启动在 `8125` 端口。

如启动无误，在浏览器打开 `http://127.0.0.1:8125/` 应看到系统首页或登录页。

## 5. 建议体验路线

为了节约老师时间，推荐按以下顺序体验：

1. 普通用户登录
2. 首页推荐与通知铃铛
3. 活动详情与报名
4. 组队大厅与查看详情
5. 消息页与通知中心
6. 个人中心
7. 活动管理或队伍管理
8. 管理员后台
9. 智能客服

整条路线控制在 10 到 15 分钟内即可完成。

## 6. 登录体验

### 操作步骤

1. 打开 `http://127.0.0.1:8125/`
2. 点击“登录”
3. 输入任意预置演示账号和密码
4. 登录成功后进入首页

### 建议体验点

- 页面是否可正常跳转
- 登录后是否显示个性化首页内容
- 右上角是否能看到通知未读数量

### 说明

如果老师想体验注册或邮箱验证码登录，也可以操作，但现场展示更建议直接用预置账号，避免受邮箱配置或网络影响。

## 7. 首页推荐与发现体验

### 操作步骤

1. 登录后停留在首页
2. 观察推荐活动模块
3. 观察推荐组队模块
4. 观察活动速览区域
5. 点击右上角通知铃铛

### 建议体验点

- 推荐活动和推荐组队是否与用户画像相关
- 首页是否同时覆盖活动和组队两条主线
- 通知铃铛是否展示未读数量
- 点击铃铛后是否进入通知中心，而不是仅通知预览

### 推荐演示方式

可以先用一个账号登录观察推荐内容，再退出并切换到另一个兴趣差异明显的账号登录，对比首页推荐变化。

## 8. 活动模块体验

### 8.1 浏览活动与查看详情

操作步骤：

1. 从首页或活动大厅进入某个活动详情页
2. 查看活动标题、时间、地点、标签、人数、简介
3. 观察是否支持收藏、报名、联系发布者

建议体验点：

- 活动信息是否完整
- 活动详情页是否清晰展示人数和时间状态
- 活动是否支持报名和收藏

### 8.2 报名活动

操作步骤：

1. 在活动详情页点击“报名活动”
2. 填写报名附言或简介
3. 提交报名
4. 返回消息页或通知中心查看反馈

建议体验点：

- 报名后是否生成对应通知
- 个人中心中“我参加的活动”是否同步出现该活动
- 如果该活动开启了群聊，后续审批通过后能否进入活动群聊

### 8.3 取消报名

操作步骤：

1. 在已报名活动详情页点击取消报名
2. 返回通知中心查看通知文案

建议体验点：

- 取消报名后通知是否显示具体人名，而不是“有同学取消了报名”
- 活动管理侧统计是否同步更新

## 9. 组队模块体验

### 9.1 浏览组队与查看详情

操作步骤：

1. 进入组队大厅
2. 任选一个队伍卡片
3. 点击“查看详情”
4. 查看完整队伍介绍
5. 查看队伍发起人信息

建议体验点：

- 长描述是否可以在详情弹层中完整查看
- 组队卡片是否只保留摘要，避免列表过于拥挤
- 是否只提供“联系组队发起人”，不再混入活动发起人联系入口

### 9.2 申请加入队伍

操作步骤：

1. 在组队详情中点击“申请加入”
2. 填写申请信息
3. 提交申请
4. 查看通知或等待队长审批

建议体验点：

- 申请动作是否成功
- 通知中心是否产生对应通知
- 队长审批后是否能进入队伍群聊

## 10. 消息与通知体验

### 10.1 消息页结构体验

操作步骤：

1. 进入消息页
2. 观察页面是否分为“私聊 / 群聊 / 通知预览”三块
3. 分别点击一条私聊、一条活动群聊或队伍群聊

建议体验点：

- 活动联系是否已经并入私聊，而不是独立一块
- 队伍聊天是否已经和活动群聊统一放到“群聊”里
- 消息页是否不再承担管理入口语义

### 10.2 通知中心体验

操作步骤：

1. 从消息页通知预览点击“查看更多通知”或从首页铃铛进入通知中心
2. 观察通知列表
3. 分别切换“全部 / 未读 / 已读”
4. 点击一条通知查看详情
5. 尝试删除一条通知
6. 点击“一键全部已读”
7. 体验分页切换

建议体验点：

- 通知筛选是否准确
- 单条查看是否自动标记已读
- 删除和一键全部已读是否生效
- 页码信息是否和翻页按钮在同一栏中展示

## 11. 个人中心体验

### 操作步骤

1. 进入个人中心
2. 查看顶部个人资料与统计信息
3. 进入“我参加的活动”
4. 进入“我发布的活动”
5. 进入“我参加的组队”
6. 进入“我发起的组队”

### 建议体验点

- 活动和组队是否都采用“参加 / 发起（发布）”两条线
- “我参加的组队”是否更偏聊天和参与语义
- “我发起的组队”是否进入管理页
- 记录过多时是否通过分页或滚动区域进行承载，而不是无限堆叠

## 12. 活动管理体验

建议使用 `org / org123` 登录体验。

### 操作步骤

1. 登录活动组织者账号
2. 从个人中心“我发布的活动”进入某个活动管理页
3. 查看顶部概览、容量状态、报名概览
4. 编辑活动内容并保存
5. 在审批区处理报名申请
6. 开启或关闭活动群聊
7. 开启或关闭“围绕该活动继续发起组队”

### 建议体验点

- 管理页是否可以预填、保存、重置
- 保存后详情页和列表页是否同步更新
- 满员后是否仍可管理审批，只是不能继续直接突破名额通过新申请
- 关闭联动组队后，活动详情页是否不再展示关联队伍

## 13. 队伍管理体验

建议使用自己发起了队伍的演示账号体验。

### 操作步骤

1. 从个人中心“我发起的组队”进入队伍管理页
2. 查看队伍概览、成员情况、申请进度
3. 编辑队伍资料并保存
4. 审批入队申请
5. 进入队伍群聊查看沟通效果

### 建议体验点

- 队伍资料是否可编辑
- 是否可查看申请人详情
- 队长管理和聊天是否已经在入口语义上拆开

## 14. 后台管理体验

建议使用 `admin / admin123` 登录体验。

### 操作步骤

1. 登录管理员账号
2. 进入后台页面
3. 查看平台统计总览
4. 查看待审核活动列表
5. 审核某个活动
6. 查看用户管理
7. 查看标签管理
8. 查看推荐位管理

### 建议体验点

- 后台是否具备清晰的管理入口
- 审核和用户状态管理是否可见
- 推荐位管理是否能体现平台运营能力

## 15. 智能客服体验

### 操作步骤

1. 进入智能客服页面
2. 输入常见问题，例如：
   - 如何报名活动？
   - 如何申请加入队伍？
   - 为什么我看不到通知？
   - 如何开启活动群聊？
   - 如何查看我发起的组队？
3. 观察客服回答
4. 尝试输入超出知识库的问题，观察是否提示转人工

### 建议体验点

- 客服能否基于知识库给出清晰回答
- 客服是否支持多轮对话
- 不确定问题是否明确建议转人工，而不是胡乱编造

## 16. 建议老师重点体验的 3 条闭环

如果时间有限，建议优先完成以下三条闭环。

### 闭环一：普通学生体验

1. 登录普通账号
2. 浏览推荐活动
3. 报名一个活动
4. 查看消息和通知
5. 在个人中心查看参加记录

### 闭环二：组队协作体验

1. 进入组队大厅
2. 查看某个队伍详情
3. 申请加入队伍
4. 切换到队长账号审批申请
5. 进入队伍群聊

### 闭环三：平台管理体验

1. 切换管理员账号
2. 进入后台
3. 审核活动
4. 查看用户和推荐位管理

## 17. 现场常见问题与处理建议

### 17.1 页面打不开

请先确认访问的是 `http://127.0.0.1:8125/`，而不是本地文件路径。

### 17.2 页面能打开但没有数据

请确认后端 `8080` 服务和本地代理 `8125` 都已启动。

### 17.3 邮箱验证码无法收到

演示时建议直接使用预置账号。邮箱收发依赖 SMTP 配置和网络环境，不建议把现场展示建立在邮箱链路上。

### 17.4 推荐结果看起来差别不明显

建议切换兴趣画像差异较大的两个账号，例如 `chenze` 和 `gumingzhe`，再对比首页推荐结果。

### 17.5 智能客服回答不理想

可优先提问平台使用类问题；如果知识库未覆盖，可测试“转人工服务”能力。

## 18. 展示结束建议

老师完成体验后，如果需要快速总结本系统能力，可按以下三点理解：

1. 本系统已经形成“活动 + 组队 + 消息 + 通知 + 管理 + 客服”的完整业务闭环。
2. 本系统不仅支持普通学生使用，也支持发布者、队长和管理员多角色协同。
3. 本系统已经具备推荐和智能客服两类智能化能力的可展示基础。
