# 校园活动智能推荐与组队平台期末展示功能需求清单

## 1. 文档目的

本清单面向期末展示和现场验收场景，用于帮助老师快速理解本系统目前已经具备的核心功能、推荐体验路径以及验收重点。

本次展示建议以“老师可直接上手体验”为目标，不要求老师阅读代码或理解部署细节，只需根据功能清单和操作说明书完成体验即可。

推荐访问入口：

- 前端统一访问地址：`http://127.0.0.1:8125/`
- 后端服务地址：`http://127.0.0.1:8080/`

说明：

- 演示时优先使用本地 HTTP 代理 `8125`，不要直接用 `file://` 打开 HTML 页面。
- 如无特殊说明，老师只需通过浏览器访问前端地址即可体验主要功能。

## 2. 系统定位

本系统是一个面向校园场景的“活动发现 + 报名审核 + 组队协作 + 消息通知 + 智能客服 + 后台管理”一体化平台，支持普通学生、活动组织者、队伍发起者和管理员等多角色使用。

## 3. 角色与体验目标

### 3.1 普通学生

可体验目标：

- 浏览和搜索活动
- 查看推荐活动与推荐组队
- 收藏活动、报名活动
- 浏览组队信息、申请加入队伍
- 使用私聊、群聊、通知中心
- 在个人中心查看参加记录
- 使用智能客服咨询平台问题

### 3.2 活动发布者

可体验目标：

- 发布活动
- 管理已发布活动
- 审批报名申请
- 开启或关闭活动群聊
- 控制活动是否继续开放联动组队
- 查看活动通知和聊天协作

### 3.3 队伍发起者

可体验目标：

- 发起组队
- 管理队伍资料
- 审批入队申请
- 使用队伍群聊
- 查看自己发起的组队与已参加的组队

### 3.4 管理员

可体验目标：

- 查看后台统计数据
- 审核活动
- 管理用户状态
- 管理标签
- 配置推荐位

## 4. 功能需求清单

以下清单按模块组织，可直接作为展示与验收目录使用。

### 4.1 账号与身份模块

功能要求：

- 支持用户名密码登录
- 支持邮箱验证码注册
- 支持邮箱验证码登录
- 支持找回密码
- 支持绑定邮箱、换绑邮箱、邮箱验证码修改密码
- 支持兴趣标签初始化与维护

验收重点：

- 老师可直接使用预置演示账号登录
- 登录后可正常进入首页、消息页、个人中心等需要鉴权的页面
- 兴趣标签可影响推荐结果展示

### 4.2 首页与发现模块

功能要求：

- 首页可展示推荐活动
- 首页可展示推荐组队
- 首页可展示活动速览
- 首页右上角通知铃铛显示未读数量
- 可从首页跳转到通知中心
- 发现页支持活动和组队内容浏览

验收重点：

- 不同演示账号登录后，推荐活动和推荐组队存在差异
- 未读通知数与通知中心内容一致
- 首页展示内容控制在适合展示的数量范围内，避免过长列表影响体验

### 4.3 活动模块

功能要求：

- 支持活动发布
- 支持活动浏览、详情查看、收藏
- 支持活动报名与取消报名
- 支持活动联系人快捷联系
- 支持活动群聊开启、关闭和进入聊天
- 支持活动管理页编辑活动资料
- 支持报名审批、通过、拒绝、移出活动
- 满员后仍可管理，但不能直接突破容量继续通过
- 支持活动联动组队开关

验收重点：

- 普通用户可完整完成“浏览活动 -> 报名活动 -> 查看通知”的闭环
- 活动发布者可完整完成“发布活动 -> 审批报名 -> 群聊协作”的闭环
- 关闭活动联动组队后，活动详情页不再展示关联队伍入口

### 4.4 组队模块

功能要求：

- 支持自由组队和活动关联组队
- 支持组队大厅浏览、筛选、查看详情
- 支持申请加入队伍
- 支持联系组队发起人
- 支持查看完整队伍详情，解决长描述展示不全问题
- 支持队长管理队伍资料
- 支持审批入队申请
- 支持队伍群聊
- 支持区分“我参加的组队”和“我发起的组队”

验收重点：

- 普通用户可完成“浏览组队 -> 查看详情 -> 申请加入 -> 等待审批”的流程
- 队长可完成“审批申请 -> 进入群聊 -> 管理队伍”的流程
- 活动关联组队仅保留“联系组队发起人”，避免和活动联系人混淆

### 4.5 推荐与搜索模块

功能要求：

- 支持推荐活动
- 支持推荐组队
- 推荐结果综合考虑兴趣标签、历史参加记录、收藏、点击、报名、组队互动等行为
- 支持关键词搜索
- 支持活动与组队统一搜索体验

验收重点：

- 不同兴趣画像账号的首页推荐存在可见差异
- 推荐结果不是单纯按发布时间排序
- 搜索可以定位活动和组队内容

说明：

- 当前项目已具备推荐入口、行为基础数据和推荐接口，适合现场演示“个性化推荐”的产品效果。

### 4.6 消息与通知模块

功能要求：

- 消息页按“私聊 / 群聊 / 通知预览”组织
- 私聊支持用户之间 1v1 联系
- 群聊支持活动群聊和队伍群聊
- 通知预览展示最近通知
- 通知中心支持：
  - 全部通知
  - 仅看未读
  - 仅看已读
  - 单条已读
  - 一键全部已读
  - 单条删除
  - 分页浏览
- 半年前通知自动清理

验收重点：

- 老师可在消息页快速理解平台沟通结构
- 通知中心的筛选、删除、已读操作可正常工作
- 通知文案应具体到人名，不使用“有同学”这类模糊表达

### 4.7 个人中心模块

功能要求：

- 支持查看和编辑个人资料
- 支持查看我参加的活动
- 支持查看我发布的活动
- 支持查看我参加的组队
- 支持查看我发起的组队
- 支持查看收藏记录和参与记录

验收重点：

- 活动与组队入口语义对齐
- “参加”和“发起/发布”两条线清晰分离
- 参加型入口以进入详情或聊天为主，管理型入口以进入管理页为主

### 4.8 智能客服模块

功能要求：

- 提供专门的智能客服页面
- 基于知识库回答平台使用问题
- 支持多轮对话
- 无法准确回答时支持转人工服务
- 支持覆盖注册、报名、组队、消息、通知、推荐、后台等常见问题

验收重点：

- 老师可直接询问“如何报名活动”“如何申请组队”“为什么看不到通知”等问题
- 客服能给出结构化回答
- 知识库无法覆盖的问题可明确提示转人工

### 4.9 后台管理模块

功能要求：

- 支持管理员登录后台
- 支持查看统计总览
- 支持活动审核
- 支持用户状态管理
- 支持标签管理
- 支持推荐位管理

验收重点：

- 管理员可从后台直接看到平台运营视角的数据与审核入口
- 待审核活动、用户状态变更、推荐位配置均可体验

## 5. 推荐体验清单

老师现场体验时，建议至少完成以下 10 个关键动作：

1. 使用演示账号登录系统。
2. 在首页观察推荐活动、推荐组队和未读通知数量。
3. 进入活动详情并完成一次报名或取消报名体验。
4. 进入组队大厅，查看队伍详情并发起入队申请。
5. 打开消息页，区分私聊、群聊和通知预览。
6. 进入通知中心，测试筛选、已读和删除功能。
7. 打开个人中心，查看“我参加的活动 / 我发布的活动 / 我参加的组队 / 我发起的组队”。
8. 使用活动发布者或队长账号体验审批功能。
9. 使用管理员账号进入后台完成审核体验。
10. 进入智能客服页面提问并观察知识库回答效果。

## 6. 建议展示顺序

为保证老师在有限时间内快速感知系统完整度，建议展示顺序如下：

1. 登录
2. 首页推荐与通知铃铛
3. 活动详情与报名
4. 组队大厅与申请
5. 消息页与通知中心
6. 个人中心
7. 活动管理或队伍管理
8. 后台管理
9. 智能客服

## 7. 验收建议

如果老师仅做简短体验，建议重点观察以下四类能力：

- 业务是否形成闭环：从浏览到报名、从申请到审批、从通知到反馈是否连贯
- 多角色是否清晰：普通学生、发布者、队长、管理员是否各自有明确入口
- 页面逻辑是否统一：活动和组队是否具有一致的信息架构和记录语义
- 智能化能力是否具备基础：推荐与智能客服是否已具备可展示的效果
